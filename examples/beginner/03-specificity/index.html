Specificity

How Specificity Works

specificity = (A, B, C)

A — ID selectors (1,0,0)

#hero — highest weight

B — class / pseudo-class / attribute (0,1,0)

.btn, :hover, [type]

C — element / pseudo-element (0,0,1)

div, ::before

Compare A first, then B, then C. If all three are tied, the last declaration wins.

Specificity Scores by Selector Type

Selector Type Increments Example Score
Universal * None * (0,0,0)
Element / pseudo-element C div, ::before (0,0,1)
Class / pseudo-class / attribute B .btn, :hover, [type] (0,1,0)
ID A #main (1,0,0)

Common Pitfalls

ID wins

#sidebar (1,0,0) beats .sidebar-widget .nav (0,2,0) — IDs are hard to override

chained classes

.card.primary.featured (0,3,0) — chained classes add up

Boosting Specificity

.button { background: blue; }  .button.button { background: green; }

.button

.button (0,1,0) — blue

.button.button

.button.button (0,2,0) — wins without !important

Tie-Breaking

.first { color: red; }  .second { color: blue; }

identical specificity

Both are (0,1,0) — the last declaration wins (blue)

Specificity vs Cascade

Specificity is just one stage. Before it, the cascade checks origin (user agent vs authored) and !important declarations. Inline styles (style="") are resolved at a different cascade step — not through specificity.
