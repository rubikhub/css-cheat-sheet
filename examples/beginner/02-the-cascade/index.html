The Cascade

How the Cascade Works

cascade = position & order → specificity → origin → importance

1 Position & Order

Last declared rule wins on ties

2 Specificity

Strongest selector wins

3 Origin

Authored CSS beats browser defaults

4 Importance

!important wins over normal rules

The cascade runs these four stages in order — earlier stages beat later ones.

Stage 1: Position & Order of Appearance

button { color: red; } button { color: blue; } /* blue wins */

two rules, later wins

Same stylesheet, two rules — the later one wins (purple)

last declaration wins

Same rule, two declarations — the last one wins (orange)

two stylesheets

style.css sets red, other-style.css sets green — later link wins (green)

Applies to rules in the same stylesheet, in different <style> / <link> elements, and to declarations within one rule.

Stage 2: Specificity

p { color: red; } /* (0,0,1) */  .highlight { color: blue; } /* (0,1,0) */

p — red

Element selector only: (0,0,1)

.highlight — blue

Class selector beats element: (0,1,0) wins

.highlight wins even though the p rule comes first — specificity outranks position.

user agent → local user → authored → !important

Stage 4: Importance

.button { color: blue; } .button-special { color: red !important; }

normal rule

Normal declaration — blue

!important wins

!important overrides normal rules regardless of specificity — red

Least to most important: normal → @animation → !important → @transition. Avoid !important when possible — it makes CSS harder to override.
